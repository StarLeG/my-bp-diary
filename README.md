[![Тесты](https://github.com/StarLeG/my-bp-diary/actions/workflows/tests.yml/badge.svg)](https://github.com/StarLeG/my-bp-diary/actions/workflows/tests.yml)

Telegram-бот для ведения дневника артериального давления: быстрая запись
кнопками или текстом, события дня, напоминания о лекарствах, визиты к врачу,
статистика и выгрузки для приёма. Бесплатный, без рекламы и платных подписок.

- **Быстро**: запись давления — калькулятор одним экраном или строка «128/82 70» в чат.
- **Полезно для врача**: дневник с событиями дня, динамика, CSV и PDF за любой период.
- **С заботой**: напоминания об измерениях и лекарствах без спама и давления.

## Возможности

- **Запись давления** — калькулятор одним экраном (систолическое / диастолическое /
  пульс, «Другое», «Пропустить») или текстом «128/82 70»; самочувствие и заметка —
  по желанию. Замер за прошедшее время — в архиве, глубина не ограничена.
- **События дня** («➕ Добавить запись»): давление и пульс, приём лекарства,
  прогулка / активность, питание (соль / кофе / алкоголь), стресс / самочувствие,
  сон, заметка — с указанием времени; всё вместе показывает **«Лента дня»**
  с фильтрами.
- **Три замера в день** (утро / обед / вечер) с напоминаниями; после «Приняли
  лекарство?» → «Да» бот напомнит повторить замер через 30 / 60 / 120 минут.
- **Лекарства**: свой список с дозировками и слотами приёма, отметки
  «принял / пропустил», приверженность «принято X из Y» в статистике.
- **Напоминания**: режим каждого слота (замеры и лекарства / только лекарства /
  только замеры), тихий повтор «если не ответил», пауза на 1 / 3 / 7 дней.
- **Визиты и анализы**: план визитов к врачу и обследований, напоминания
  (вечером, за 2 часа, утром и после), заключения — текстом и фото.
- **Статистика**: средние (в том числе по дням), мин/макс, тренд, сравнение
  с целью, свой период; экспорт CSV (измерения и приёмы лекарств) и PDF-отчёт —
  чтобы показать врачу.
- **Личный кабинет** (с компьютера): история с фильтрами и графиками, добавление,
  правка и удаление записей, импорт CSV, лекарства, напоминания, визиты. Вход —
  по одноразовой ссылке из бота или e-mail + пароль (хранится только хеш Argon2id).
- **Кабинет врача**: доступ по защищённой ссылке с подтверждением — только чтение
  и комментарии, данные пациента врач изменить не может.
- **Крупный режим** для людей с плохим зрением — крупный кегль и кнопки.
- **Многопользовательность**: данные каждого пользователя изолированы.

## Как это работает

1. `/start` — короткая настройка: цели давления, часовой пояс, расписание замеров.
2. Бот напоминает утром / днём / вечером → «Записать давление» → значения → «✅ Записано».
3. «Приняли лекарство?» → «Да» → через выбранное время — вежливый повтор замера.
4. В течение дня — «➕ Добавить запись» для событий, а «Лента дня» покажет всё вместе.
5. Перед визитом к врачу — «Статистика», CSV и PDF за период; сам визит удобно
   запланировать в «Визитах и анализах».
6. Нужен большой экран — кнопка «Личный кабинет» пришлёт ссылку входа.

При давлении ≥180/110 бот вежливо предложит обратиться к врачу — без диагнозов
и медицинских советов.

## Быстрый старт

```bash
git clone https://github.com/StarLeG/my-bp-diary.git
cd my-bp-diary
uv sync
cp .env.example .env   # заполните BOT_TOKEN и остальные переменные
uv run python -m bot
```

Требуется Python 3.11+ и [uv](https://docs.astral.sh/uv/).

## Переменные окружения

Копируются из `.env.example` в `.env` (файл `.env` не попадает в git):

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather (только env, никогда в коде) |
| `BOT_PROXY` | SOCKS/HTTP-прокси для Telegram API; пусто = без прокси |
| `SUPPORT_URL` | ссылка на страницу поддержки; пусто = кнопка скрыта |
| `AUTHOR_CONTACT` | контакт автора; пусто = кнопка скрыта |
| `GROUP_URL` | ссылка на сообщество в Telegram; пусто = кнопка «Наше сообщество» скрыта |
| `DB_PATH` | путь к файлу SQLite (по умолчанию `data/bot.sqlite3`) |
| `DEFAULT_TIMEZONE` | часовой пояс по умолчанию (IANA) |
| `LOG_LEVEL` | уровень логирования |
| `ADMIN_TELEGRAM_IDS` | Telegram ID администраторов через запятую (админ-панель); пусто = админ-панель выключена |
| `WEB_SECRET_KEY` | секрет личного кабинета (сессии и magic link) |
| `CABINET_URL` | base URL личного кабинета; пусто = кабинет не развёрнут |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | почта для писем врачу со ссылкой доступа (SPEC §21); пустой `SMTP_HOST` = письма не отправляются, ссылка — пациенту для пересылки |
| `PRIVACY_URL` | страница «Персональные данные» (SPEC §16.1): ссылки из экранов согласия; пустое значение — ошибка при старте |
| `BACKUP_ENCRYPTION_KEY`, `BACKUP_DIR` | шифрование и каталог резервных копий (SPEC §20); копии хранятся не дольше 14 дней |
| `S3_ENDPOINT_URL`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | off-site хранилище копий бэкапов (SPEC §18.3); пусто = только локальные копии |
| `DELETION_LOG_KEY`, `DELETION_LOG_PATH` | журнал удалений (SPEC §19); ключ обязателен при `BACKUP_ENCRYPTION_KEY`. После ручного восстановления копии: `python -m bot.services.deletion_log --apply` |

Для E2E-тестов QA-стенда используются `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`,
`TELEGRAM_TEST_PHONE`, `TELETHON_SESSION`, `QA_BOT_USERNAME` (см. `qa/`).

## Запуск в Docker

Собирается один образ (бот + личный кабинет), запускается через Docker Compose:

```bash
./deploy.sh          # Linux/macOS
.\deploy.ps1         # Windows PowerShell
```

Подкоманды:

| Команда | Действие |
|---|---|
| `up` (по умолчанию) | собрать образ и запустить бота и личный кабинет |
| `https` | то же + HTTPS (Caddy с Let's Encrypt; нужен `CABINET_URL` и DNS) |
| `logs` | логи всех сервисов |
| `ps` | состояние контейнеров |
| `down` | остановить и убрать контейнеры |

Примечания:

- Кабинет слушает только `127.0.0.1:8000`; наружу — через Caddy (HTTPS, профиль `https`).
- Секреты (`BOT_TOKEN`, `WEB_SECRET_KEY`) задаются только в `.env` — в образ и git они не попадают.
- SQLite хранится на общем томе `bot-data` и переживает пересоздание контейнеров.

## Веб-части

- `web/landing/` — статический лендинг: как работает бот, кадры экранов, руководство,
  FAQ, секции «Автор», «Поддержать проект» и «Для бизнеса». Отдаётся контейнером
  `nginx:alpine` с конфигом `deploy/landing-nginx.conf` (кеш, gzip):

  ```bash
  docker rm -f bp-landing
  docker run -d --name bp-landing --restart unless-stopped -p 127.0.0.1:8081:80 \
    -v "$PWD/web/landing:/usr/share/nginx/html:ro" \
    -v "$PWD/deploy/landing-nginx.conf:/etc/nginx/conf.d/default.conf:ro" \
    nginx:alpine
  docker network connect nginx-proxy-manager_default bp-landing   # если перед ним NPM
  ```

  Tailwind CSS собран заранее в `web/landing/css/tailwind.css`. После правки классов в
  разметке пересоберите его: `uv run python tools/landing/build_css.py`. Скрипт скачивает
  Tailwind CLI v3.4.17 в `.cache/tailwind/` и сверяет SHA-256. Если GitHub отдаёт файл
  медленно, скачайте `tailwindcss-<платформа>` вручную и положите туда как
  `tailwindcss-3.4.17-<платформа>`.
  Иконки: `uv run --group qa python tools/landing/make_icons.py`; превью ссылки (`img/og.png`):
  `uv run --group qa python -m qa.screenshots.make_og`. Права на сайт в Яндекс.Вебмастере и
  Google Search Console подтверждены метатегами в `index.html` (и файлом
  `yandex_4226e1494c17becc.html` для Яндекса).
- `web/cabinet/` — личный кабинет (FastAPI + Jinja2): вход по одноразовой ссылке из бота
  (15 минут) или e-mail + пароль (хранится только хеш Argon2id); сессии 7 дней, CSRF,
  ограничение попыток входа. Прямой регистрации «с улицы» нет — привязка только через бота.
  Запускается отдельным процессом (`uvicorn web.cabinet.app:app`) или сервисом Docker Compose;
  HTTPS — за reverse proxy (Let's Encrypt).

## Структура проекта

```
bot/          — бот: хендлеры, сервисы, планировщик напоминаний (APScheduler)
web/landing/  — статический лендинг (Tailwind CSS)
web/cabinet/  — личный кабинет (FastAPI, Argon2id, magic link) и кабинет врача
tests/        — юнит-тесты (pytest), включая тесты конкурентности
qa/           — нагрузочные тесты, авто-приёмка перед релизом и E2E (Telethon, Playwright)
doc/          — ТЗ (TZ.md) и спецификация (SPEC.md)
tools/        — сборка CSS лендинга, скриншоты и служебные скрипты
deploy/       — конфиги развёртывания (nginx лендинга, Caddy)
```

## Тесты

```bash
uv run pytest -q --cov=bot --cov-fail-under=90
```

3754 теста; покрытие `bot/` — 97% строк. Требование спецификации: ≥ 90% строк,
бизнес-логика — 100% веток, обязательны тесты конкурентности.

Те же тесты запускаются в GitHub Actions (Python 3.11–3.14) при каждом push и
pull request — статус сборки виден бейджем в начале страницы.

Отдельно в `qa/` живут нагрузочные тесты (20 одновременных пользователей, база
на 50 000 измерений, критерии SPEC §22) и авто-приёмка перед релизом; E2E бота —
Telethon, кабинета — Playwright.
