# Таблицы, карточки и кнопки кабинета: UX-вопросы

Три проблемы по скриншотам ЛК (разделы «Визиты и анализы» и «Управление лекарствами»):

1. **Таблица «Скоро» неудобна**: каждая строка — форма с инпутами (дата, время, название, заметка), из-за этого
   таблица шире экрана (горизонтальный скролл), «Вид» переносится в две строки, текст заметки не помещается
   в узкий `<input>` и обрезается («Диагностический цент г.»), кнопка удаления уезжает за правый край.
2. **Кнопки строк перегружают**: повторяющиеся пары «Сохранить» + залитая красная «Удалить» в каждой строке
   («Лекарства», «Визиты») — много красного, в «Истории» при этом уже используются иконки «✏️»/«🗑».
   Вид кнопок и паттерн правки отличаются от секции к секции и от кабинета врача.
3. **«История записей» будет очень длинной** — плоская таблица всех записей периода, хочется сворачивания
   и группировки.

Требование: единообразие на всей странице ЛК **и** в кабинете врача (одни и те же роли кнопок, один паттерн
правки, одна раскладка таблиц).

Сверено с `doc/SPEC.md`:
- §16.2 — «История записей» (колонки, подсветка зон, легенда, строки-карточки < 768 px), «Управление
  лекарствами» (CRUD), «Визиты и анализы» (0.5.8: две таблицы «Скоро»/«Прошедшие», колонки Дата, Время, Вид,
  Название, Заметка, действия; «✏️», «Отменить», «🗑», «Был(а)»/«Не был(а)», «Перенесли на…»),
  «Добавление, правка и удаление записей» (форма над таблицей, «✏️»/«🗑» у строки, подтверждение удаления),
  «Средние по дням» (зона дня — худшая из зон округлённых средних САД/ДАД);
- §21 — кабинет врача: та же «История записей» без действий, заметки врача, только чтение;
- §11 (тон текстов), §1 (минимум трения).

Сверено с кодом:
- `web/cabinet/templates/dashboard.html:553-590` — «Скоро»: инлайн-инпуты + «✏️ Сохранить» / «Отменить» / «🗑»
  (`btn-danger`, уезжает за край); `dashboard.html:486-520` — «Лекарства»: инлайн-правка, пары
  «Сохранить» (`btn-ghost`) + «Удалить» (`btn-danger`); `dashboard.html:441-476` — «История»: иконки «✏️»/«🗑»;
- `web/cabinet/templates/doctor_dashboard.html:204-235` — история врача: та же таблица без колонки действий;
- `web/cabinet/static/style.css:274-277` — `td.note { max-width: 260px }` (заметка сжата);
  `style.css:250-252` — `.table-scroll` (горизонтальный скролл); `style.css:486-521` — строки-карточки
  только у `.stacked-table` («История» и «Средние по дням»), у «Лекарств» и «Визитов» на мобильных — скролл.

Что **не** трогаем: бот (§6.13 — своя логика кнопок), PDF/CSV-экспорт, графики и «Средние по дням»,
легенду зон, подсветку строк истории, медицинские тексты (§1 non-goals).

**Как отвечать:** букву варианта (или свой) — в строку «Ответ». «Моё мнение» — только мнение.
Код не пишу до ответов, правок SPEC и её утверждения.

## Как это может выглядеть (наброски по моим вариантам)

**«Визиты и анализы» — карточки** (вариант В1-А):

```
Визиты и анализы

Скоро
┌─────────────────────────────────────────────────┐
│ 🩺 Визит к врачу             пт, 12.11 · 13:20  │
│ Кардиолог                                       │
│ Центр улыбка                                    │
│                             [✏️ Изменить]  [⋯]  │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│ 🧪 Анализы                  сб, 13.11 · 07:30   │
│ Общий анализ крови                              │
│ Хеликс, натощак                                 │
│                             [✏️ Изменить]  [⋯]  │
└─────────────────────────────────────────────────┘

[➕ Добавить]
```

Заметка — целиком, переносом; пустая заметка — строка не показывается. «⋯» (CSS-only `<details>`, без JS) —
«Отменить визит» и «Удалить…». «✏️ Изменить» раскрывает ту же форму, что «➕ Добавить» (предзаполненную):

```
┌─────────────────────────────────────────────────┐
│ Вид       [🩺 Визит к врачу ▾]                  │
│ Название  [Кардиолог                       ]    │
│ Дата      [12.11.2026]     Время [13:20]        │
│ Заметка   [Центр улыбка                   ]    │
│ [Сохранить]  [Отмена]                [🗑 Удалить]│
└─────────────────────────────────────────────────┘
```

**«Прошедшие» — карточки со статусом** (В2):

```
Прошедшие
┌─────────────────────────────────────────────────┐
│ 🩺 Визит к врачу              вт, 10.11 · 10:30 │
│ Кардиолог · ✓ состоялся                          │
│                             [✏️ Изменить]  [⋯]  │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│ 🧪 Анализы                   пн, 09.11 · 07:30  │
│ Общий анализ крови · ждёт отметки                │
│        [✓ Сдал(а)]  [Не сдал(а)]  [Перенести]   │
└─────────────────────────────────────────────────┘
```

**«История записей» — аккордеон по дням** (В3–В4; тот же компонент в кабинете врача, без «✏️»/«🗑»):

```
История записей
[➕ Добавить измерение]  [📥 Импорт CSV]          [Свернуть все]

▼ Пт, 12.11 · 3 записи · в среднем 132/84 · 🟡
    08:15   135/85   72   Лозартан 50 мг   Норма   «хорошо выспался»   [✏️] [🗑]
    12:40   138/88   75   —                —       —                   [✏️] [🗑]
    20:10   122/78   68   Лозартан 50 мг   Норма   —                   [✏️] [🗑]
▶ Чт, 11.11 · 2 записи · в среднем 128/80 · 🟢
▶ Ср, 10.11 · 1 запись · в среднем 121/76 · 🟢
```

Заголовок дня: дата («Пт, 12.11»), число записей («3 записи» — правильная форма), средние САД/ДАД за день,
точка зоны дня — по правилу «Средних по дням» (худшая из зон округлённых средних; только жёлтая и красная,
🟢 — норма). Только дни с записями. Внутри дня — текущие колонки таблицы; на < 768 px — строки-карточки
(как сейчас). `<details>/<summary>`, без JS; кнопка «Свернуть все / Развернуть все» — короткий скрипт,
как у предотметки лекарств.

**Единые роли кнопок** (В5) — на обеих страницах:

| Роль | Вид | Где |
|---|---|---|
| Основное действие | залитая (`btn`) | «Записать», «Сохранить», «Добавить», «Импортировать», «Сохранить заметку», «Сохранить напоминания», «Войти» |
| Вторичное | призрачная (`btn-ghost`) | «Отмена», «Показать», «Скачать CSV/PDF», «Снять паузу», «✏️» в строке |
| Опасное в строке | иконка «🗑», красная, **без заливки** | строки истории, карточки визитов, лекарства |
| Опасное финал | залитая красная (`btn-danger`) | **только** кнопка «Удалить» в подтверждении |

## Секция «Визиты и анализы»

### В1. Формат списка «Скоро»

- **А** — карточки событий (набросок выше): только чтение, заметка целиком, «✏️ Изменить» раскрывает форму
  в карточке, «⋯» — «Отменить визит» / «Удалить…».
- **Б** — таблица только на чтение (Дата · Время · Вид · Название · Заметка переносом на новую строку) +
  «✏️» раскрывает форму правки под таблицей (как форма «Изменить запись» в «Истории»).
- **В** — оставить инлайн-редактирование, но уплотнить: заметка второй строкой ячейки (текстом, не инпутом),
  действия — иконками по В5, ширина инпутов фиксирована.

**Моё мнение:** А. «Скоро» обычно 1–5 событий — карточка заметнее и удобнее таблицы: заметка помещается
целиком, пропадает горизонтальный скролл (главная беда скриншота), форма правки — те же поля, что добавление
(единое правило ниже). Раскладка сквозная с мобильными строками-карточками «Истории».

**Ответ:** А — карточки событий: только чтение, заметка целиком, «✏️ Изменить» раскрывает форму в карточке, «⋯» — «Отменить визит» / «Удалить…».

Уточнение для SPEC: карточка — `<article>` с классами `.event-card`; заголовок — вид + дата/время; вторая строка — название; третья — заметка (если есть, `white-space: pre-wrap`); действия — «✏️ Изменить» (призрачная) + `<details>` «⋯» (без JS). «Отменить визит» — только у `planned`; «Удалить…» — у всех. Форма правки — та же, что добавление, предзаполнена, в раскрытом `<details>` под карточкой (не модалка — минимум JS, §1).

### В2. «Прошедшие»: формат и объём

- **А** — карточки со статусом («✓ состоялся» / «не состоялся» / «перенесён» / «отменён»), все подряд,
  новые сверху (как сейчас по объёму).
- **Б** — карточки, сгруппированные аккордеоном по месяцам («Ноябрь 2026 · 5 событий»), текущий месяц
  развёрнут, остальные свёрнуты.
- **В** — карточки, но последние 20 событий + кнопка «Показать ещё».

**Моё мнение:** Б. «Прошедшие» копятся годами (визит, перенос, анализы — по нескольку в месяц), плоский
список станет длиннее «Скоро» на порядок. Месяц — привычная единица для «а что было осенью?», аккордеон
тот же, что в «Истории» (единообразие). «Ждёт отметки» всегда сверху списка (вне групп) — их нельзя терять
в свёрнутом месяце.

**Ответ:** Б — карточки, сгруппированные аккордеоном по месяцам («Ноябрь 2026 · 5 событий»), текущий месяц развёрнут, остальные свёрнуты; «Ждёт отметки» — всегда сверху списка, вне групп.

Уточнение для SPEC: «Ждёт отметки» — `status='planned'` с прошедшей датой и прошло ≤ 3 дней; дата `starts_on < сегодня` — событие сегодняшнего дня остаётся в «Скоро» до полуночи (Н2; из пары «≤ / <» в черновике ответа принято «<» — так устроено сейчас: `is_upcoming` / `awaiting_answer`). Заголовок группы: «Ноябрь 2026 · 5 событий» (правильная форма «событие / события / событий»); группы-месяцы и события внутри — новые сверху. `<details open>` — для текущего месяца; остальные — `<details>` без `open`.

### В3. Группировка «Истории записей»

- **А** — аккордеон по дням (набросок выше), всегда; тот же partial в кабинете врача.
- **Б** — адаптивно: ≤ 14 дней — по дням; 15–92 дня — по неделям («Неделя 10.11–16.11 · 18 записей · в среднем
  130/82»); больше — по месяцам.
- **В** — без группировки, пагинация «Показать ещё 50 записей».

**Моё мнение:** А. День — естественная единица гипертоника (утро/вечер, «Средние по дням» уже по дням,
точка зоны дня уже посчитана). Недельная группировка ломает этот ритм, а пагинация прячет данные без
обзора. Заголовок дня с числом записей и средним даёт обзор, не раскрывая строки. Очень длинные периоды —
отдельным вопросом В8.

**Ответ:** А — аккордеон по дням, всегда; тот же partial в кабинете врача.

Уточнение для SPEC: заголовок дня: «Пт, 12.11 · 3 записи · в среднем 132/84 · 🟡». Точка зоны — по правилу «Средних по дням» (худшая из зон округлённых средних САД/ДАД; только жёлтая и красная; 🟢 — норма). Только дни с записями. Внутри — текущие колонки; на < 768 px — строки-карточки (как сейчас). `<details>/<summary>`, без JS; «Свернуть все / Развернуть все» — короткий скрипт, как у предотметки лекарств.

### В4. Свёртка по умолчанию

- **А** — все дни развёрнуты (как сейчас, ничего не прячется), кнопка «Свернуть все».
- **Б** — развёрнуты последние 7 дней, остальные свёрнуты; кнопка «Свернуть все / Развернуть все».
- **В** — свёрнуты все, кроме сегодня; кнопка «Развернуть все».

**Моё мнение:** Б. Дефолтный фильтр ЛК — 7 дней, при нём свёртки нет вообще (привычная картина), а при
30 днях страница сразу компактна. Кнопка-переключатель одна, текст меняется. Состояние — на время просмотра
(без сохранения в БД/куках).

**Ответ:** Б — развёрнуты последние 7 дней, остальные свёрнуты; кнопка «Свернуть все / Развернуть все».

Уточнение для SPEC: «последние 7 дней» — от сегодняшнего дня в поясе пользователя (не «7 дней от начала периода» — иначе при периоде 30 дней свёрнутыми окажутся как раз свежие). При периоде ≤ 7 дней — свёрток нет, кнопка не показывается.

## Кнопки и правка

### В5. Стиль действий в строках (единый на обеих страницах)

- **А** — иконки: в строках и карточках только «✏️» (призрачная) и «🗑» (красная иконка **без заливки**,
  `title="Удалить"`); текстовые кнопки — только в формах и подтверждениях; красная заливка — только
  финальное «Удалить» в подтверждении (таблица ролей выше).
- **Б** — текстовые кнопки везде, но единые: «Сохранить» (призрачная), «Удалить» (danger-призрачная —
  красный текст/рамка, без заливки); заливка — только в подтверждении.
- **В** — как А, но на десктопе действия строки видны при наведении (до наведения — полупрозрачные);
  на тач-устройствах всегда видны.

**Моё мнение:** А. «История» уже живёт иконками, пользователь их знает; красная заливка в каждой строке
(скриншот 2) — главный источник визуального шума. В — возможное позже усиление А, если захочется ещё тише,
но как дефолт плохо: прячет действия от клавиатуры и тача.

**Ответ:** А — иконки: в строках и карточках только «✏️» (призрачная) и «🗑» (красная иконка без заливки, `title="Удалить"`); текстовые кнопки — только в формах и подтверждениях; красная заливка — только финальное «Удалить» в подтверждении.

Уточнение для SPEC: §16.2 — таблица ролей (из наброска) + словарь подписей (7б) — как канон. §21 — история врача тем же компонентом без «✏️»/«🗑» (роли кнопок те же, действий строки нет). В (скрытие до наведения) — не сейчас: плохо для клавиатуры и тача; если захочется — отдельной задачей.

### В6. Паттерн правки «Лекарств»

Сейчас лекарства — единственный список с инлайн-инпутами и парой «Сохранить»/«Удалить» (скриншот 2).
Правка измерений — форма над таблицей (`?edit=`), правка визитов после В1 — форма в карточке.

- **А** — единое правило «посмотрел → «✏️» → форма правки (те же поля, что форма добавления, предзаполнена)»:
  у лекарств правка раскрывается формой «Изменить лекарство» (как «Добавить лекарство»), удаление — «🗑»
  с подтверждением. Строки таблицы — только чтение (Название · Дозировка · Слот).
- **Б** — оставить инлайн-правку лекарств (таблица маленькая), но кнопки и подтверждения — по В5/В7.

**Моё мнение:** А. Три разных паттерна правки в одной странице (форма сверху, инлайн, форма в карточке) —
то, что и вызывает ощущение разнобоя; единое правило проще запомнить. Малость лишнего клика у лекарств
перекрывается тем, что строка перестаёт быть формой.

**Ответ:** А — единое правило «посмотрел → «✏️» → форма правки (те же поля, что форма добавления, предзаполнена)»: у лекарств правка раскрывается формой «Изменить лекарство» (как «Добавить лекарство»), удаление — «🗑» с подтверждением. Строки таблицы — только чтение (Название · Дозировка · Слот).

Уточнение для SPEC: форма «Изменить лекарство» — тот же partial, что «Добавить лекарство», с `?edit={id}` (как правка измерения). Удаление — «🗑» в строке (по В5) → подтверждение блоком (залитая красная «Удалить» + «Отмена»); в черновике уточнения упоминалось «⋯» → «Удалить…», принято прямое «🗑» — у строки лекарства нет второго пункта меню. Инлайн-правка убирается (`dashboard.html:486-520`).

### В7. Формулировки

**7а. Действие отмены визита** (сейчас «Отменить» рядом с «Удалить» — путается и с «Отмена» формы, и с удалением):

- **А** — «Отменить визит» (для анализов — «Отменить сдачу», для обследования — «Отменить обследование»);
  подтверждение: «Отменить визит «Кардиолог — 12.11»? Он останется в «Прошедших» со статусом «Отменён».»
- **Б** — «Не состоится»; коротко, но неочевидно, что статус можно вернуть правкой.
- **В** — оставить «Отменить».

**Моё мнение:** А. Действие — смена статуса, а не удаление, полная подпись это фиксирует; хвост про
«останется в Прошедших» снимает страх потерять запись.

**Ответ:** А — «Отменить визит» (для анализов — «Отменить сдачу», для обследования — «Отменить обследование»); подтверждение: «Отменить визит «Кардиолог — 12.11»? Он останется в «Прошедших» со статусом «Отменён».»

Уточнение для SPEC: подписи по `kind`: `doctor` → «Отменить визит», `lab` → «Отменить сдачу», `exam` → «Отменить обследование». В подтверждении — название и дата: «Отменить визит «Кардиолог — 12.11»?». Статус `cancelled`. ## Длинные периоды

### В8. «История записей» за период больше 92 дней

Группировка по дням (В3) делает длинную историю компактной, но период «Свой период» не ограничен
(§16.2), и за 2 года это сотни свёрнутых дней и тысячи строк DOM.

- **А** — без ограничений (как сейчас): все дни аккордеоном, страница длинная, но полная.
- **Б** — показывать последние 92 дня периода + кнопка «Показать ещё 30 дней» (догружает более ранние);
  экспорт CSV/PDF — всегда за весь период.
- **В** — при периоде > 92 дней — текст «Выберите период до 92 дней, чтобы увидеть историю записей»
  (как «Средние по дням»); экспорт — за весь период.

**Моё мнение:** Б. Не отнимает данные (как В), не строит страницу на тысячи строк (как А); 92 дня —
та же граница, что уже принята для «Средних по дням», так что правило единообразно.

**Ответ:** Б — показывать последние 92 дня периода + кнопка «Показать ещё 30 дней» (догружает более ранние); экспорт CSV/PDF — всегда за весь период.

Уточнение для SPEC: кнопка — «Показать ещё 30 дней», состояние в URL: `?shown=N` — число показанных дней вглубь от конца периода (старт — min(92, длина периода), каждое нажатие +30, кнопка исчезает, когда показан весь период). Экспорт — за весь период, без изменений. Если период ≤ 92 дней — кнопки нет. В8 работает поверх фильтра периода: фильтр задаёт период, «Показать ещё» — сколько из него показать.
