# Веб-аудит личного кабинета пациента — 2026-11-18

**Объём.** Полный проход по кабинету пациента (`web/cabinet`) на локальном стенде:
вход, «Личная карточка», «Мои данные», «Настройки профиля», «Сводка за период»
(периоды, «Средние по дням», графики, экспорт), «История записей» (фильтры,
группировка по дням, действия строк), «Лекарства» (таблица и форма добавления),
«Визиты и анализы», «Напоминания», «Заметки врача», «Мой врач», футер. Плюс
мобильная ширина 375 px, консоль браузера, сетевые запросы, выгрузки CSV/PDF.

**Стенд и данные.** Локальный Docker-стенд (`docker compose -f docker-compose.yml`),
кабинет `http://127.0.0.1:8000`, вход `demo@example.org` / `demopass123`
(`tools/seed_demo.py` + дополнение: измерения 12–18.11.2026, Глицин в слотах
утро/обед/вечер — сценарий находки A5, события дневника, заключения).
Скриншоты — `qa/reports/screenshots/audit/`.

**Метод.** Playwright (аудит-проход по интерактивным элементам), замеры через
`window.scrollY`/DOM, проверка атрибутов форм, `fetch` выгрузок, консоль и сеть
браузера. Одна ложная тревога по ходу: смена Docker Desktop роняла локальную
сеть проброса портов (браузер и curl получали пустой ответ при живом
контейнере) — перепроверено, к продукту отношения не имеет.

**Итог.** Консоль чистая (0 ошибок/предупреждений), сетевых сбоев нет, мобильная
вёрстка без горизонтального переполнения, выгрузки работают (PDF — 200,
`%PDF-1.3`, 31 КБ). Четыре наблюдения заказчика подтверждены, три дополнительные
находки — ниже. Развилки решений — `doc/CABINET-AUDIT-QUESTIONS.md`.

## Находки

### A1. Смена периода перекидывает экран вверх ✅ подтверждено

**Где.** «Сводка за период» (`web/cabinet/templates/dashboard.html:215`),
селект `dashboard.html:221` — `<select name="days" onchange="this.form.submit()">`.

**Что.** При смене периода (селект, «Показать», выбор «Свой период») форма
уходит GET-ом на `/?days=…&date_from=…&date_to=…` **без якоря** — страница
открывается с начала, пользователь теряет место чтения.

**Замер.** Прокрутка к «Сводке» → `scrollY = 1471`; смена на «30 дней» →
`scrollY = 0`. Фильтры «Истории» при этом используют якорь (`#history`,
`dashboard.html:287`) и ведут себя правильно — есть единый образец.

**Скриншот.** `05-summary-block.png`. **→ TestUserFindings** при исправлении.

### A2. Поля «С / По» активны при «7 дней» / «30 дней» ✅ подтверждено

**Где.** `dashboard.html:229` (`date_from`), `dashboard.html:233` (`date_to`) —
`<input type="date">` всегда видимы и `disabled=false`, при любом пресете.

**Что.** Для «7 дней» / «30 дней» даты не имеют смысла: период задан пресетом,
поля открыты для ввода и путают (наблюдение заказчика: «или они должны быть
недоступными для ввода»).

**Дополнение (A3).** Выбор «Свой период» в селекте **сам** сабмитит форму с
пустыми датами: сводка молча показывает прежнее 7-дневное окно
(«Период: 12.11.2026 — 18.11.2026», 14 записей), а селект уже показывает
«Свой период» — рассинхрон видимого состояния и данных, подсказки «выберите
даты» нет. Позитивный сценарий с заполненными датами работает верно
(01.11–10.11.2026 → «Записей: 15»).

**Скриншот.** `05-summary-block.png` (поля активны при «7 дней»).

### A4. Графики: клик ничего не делает, три отдельных полотна ✅ подтверждено

**Где.** Три canvas: `bp-chart` (САД), `bp-chart-dia` (ДАД), `bp-chart-pulse`
(пульс) — `web/cabinet/static/bp-charts.js` (`new Chart(...)`, строка 75).

**Что.** `cursor: auto`, `onclick` нет, тултип Chart.js — максимум взаимодействия.
Заказчик: «при клике на график увеличить его на всю страницу и сделать 3 графика
на одном». Находка = предложение по улучшению (см. R4 вопросов).

### A5. «Лекарства»: одно лекарство — несколько строк ✅ подтверждено

**Где.** `dashboard.html:539` (секция), таблица `dashboard.html:561-…`
(колонки Название / Дозировка / Слот / Действия).

**Что.** Лекарство в нескольких слотах (`UNIQUE(user_id, name, slot)`, §4.4)
показывается строкой на каждый слот: Глицин 500 мг — три строки (Утро, Обед,
Вечер), как на скриншоте заказчика. Один препарат в глазах пользователя
«размножается»; отсюда же «принято 0 из 35 приёмов» — план считает слоты.
Мед-основание новой модели — в `doc/CABINET-AUDIT-QUESTIONS.md`, R5–R6.

**Скриншот.** `06-medications-block.png` (и `04-mobile-meds.png`).

### A6. Приверженность противоречит истории записей

**Где.** `dashboard.html:261` («принято {{…}} из {{…}} приёмов»).

**Что.** В истории строки показывают «Принято: Лозартан 50 мг» (связи
`measurement_medications`), а сводка — «принято 0 из 35 приёмов»: приверженность
считается только по `medication_logs` (§6.5), а запись из формы ЛК создаёт
только связи (решение M1-А, `doc/CABINET-MEDS-QUESTIONS.md`). Пользователь видит
противоречие между «Принято» в таблице и нулём в сводке. См. R7 вопросов.

### A7. «Напоминания»: все слоты по умолчанию в 08:00

**Где.** Блок «Напоминания», поля «Время» утро/обед/вечер — все `08:00`.

**Что.** При пустых настройках слоты показывают одинаковое время (обед и вечер —
08:00), выглядит как ошибка данных. Реалистичные умолчания (08:00 / 14:00 /
20:00) согласуются с мед-моделью равномерных интервалов (R6). Мелочь.
