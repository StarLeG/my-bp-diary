Ты — senior Python-разработчик. Нужно создать Telegram-бота для ведения дневника гипертоника.

**Репозиторий:** https://github.com/StarLeG/my-bp-diary.git

## Стек
Python 3.11+, aiogram 3.x, SQLite (на старте), SQLAlchemy 2.0 (async), Pydantic для валидации, python-dotenv для конфига.

## Ключевой UX-принцип
Минимум трения. Ввод давления — клавиатурой-калькулятором (цифры, «⌫», «C», «Готово») или числом в чат. Кнопки вместо свободного ввода везде, где это возможно. Редактируй существующее сообщение (edit_message_text / edit_message_reply_markup) вместо отправки новых, чтобы не плодить визуальный шум.

## Функционал MVP
1. /start — онбординг (2–3 экрана с кнопками, без простыней текста). Спросить: часовой пояс, целевые значения (по умолчанию 130/80), удобное время напоминаний (утро/вечер).
2. Главное меню (inline keyboard): «Записать давление», «Дневник за сегодня», «Статистика», «Настройки», «О боте / Поддержать».
3. Запись давления: бот редактирует сообщение, показывая диалог по шагам — систолическое, затем диастолическое, затем пульс (опционально, кнопка «Пропустить»). На каждом шаге — клавиатура-калькулятор (цифры, «⌫», «C», «Готово») и кнопка «Отмена»; значение можно также просто написать числом в чат — оно подтверждается сразу. Проверка ввода: целые числа в диапазонах систолическое 70–260, диастолическое 40–160, пульс 30–220; систолическое должно быть выше диастолического. После сохранения — сводка введённых данных:
   ```
   ✅ Записано
   Систолическое: 135
   Диастолическое: 85
   Пульс: 72
   ```
   (если пульс пропущен — «Пульс: —»). Ниже кнопки: «✏️ Изменить» (повторяет шаги ввода, после сохранения — «✅ Обновлено»), «Добавить заметку», «Приняли лекарство?», «Самочувствие», «В меню».
4. Опционально после записи: «Приняли лекарство?» («Да»/«Нет») и «Самочувствие» (Норма/Головная боль/Слабость/Другое). Не навязывать — если пользователь ушёл в меню, не переспрашивать. При «Да» и настроенных лекарствах — мультивыбор «Какие лекарства приняли?» с галочками (строка на приём: лекарство, дозировка, слот) и кнопкой «Готово»: отмеченные попадают в журнал приёмов (medication_logs, статус taken) и в приверженность, а также связываются с записью измерения (measurement_medications) — перечень виден в «Истории записей» личного кабинета.
5. Просмотр записей за сегодня (список с временем и показателями).
6. Статистика за неделю/месяц: среднее систолическое/диастолическое, мин/макс, количество измерений, тренд (растёт/падает/стабильно). Без графиков — текстовая сводка + опционально CSV-файл для врача.
7. Настройки: время напоминаний, целевые значения, экспорт в CSV, смена часового пояса.
8. Напоминания — интерактивные: сообщение с кнопками «Записать сейчас» / «Через 30 мин» / «Сегодня пропускаю». Не просто «Пора мерить давление».

## Блок «Об авторе и поддержке» (обязателен)
- В главном меню — кнопка «О боте / Поддержать».
- Экран «О боте»: 2–3 абзаца от первого лица. Кто автор, зачем сделан бот, почему он бесплатный и без рекламы. Тон человеческий, без маркетинга. Пример: «Бота пишет один разработчик в свободное время. Он бесплатный и без рекламы. Если бот помогает вам вести дневник — можете поддержать разработку. Это не обязательно: все функции доступны без доната».
- Под текстом — inline-кнопки: «Поддержать проект» (ссылка на страницу поддержки), «Написать автору» (контакт из конфига), «Назад».
- Экран «Поддержать»: краткое объяснение, на что идут деньги (хостинг, развитие бота, тестирование на реальных тонометрах с разными протоколами). Ниже — кнопка-ссылка «Перейти на страницу поддержки».
- ВАЖНО: реквизиты (номера карт, IBAN, кошельки, УНП, ФИО) внутри кода бота НЕ хранить. Только ссылка на страницу поддержки — секцию «Поддержать проект» (якорь #support) лендинга. Реквизиты размещаются там же.
- Ссылки и контакты — только через переменные окружения: SUPPORT_URL (пока плейсхолдер, страница появится позже), AUTHOR_CONTACT. Не хардкодить в хендлерах.
- В /start и в футере экрана «Статистика» — одна ненавязчивая строка: «Бот бесплатный. Поддержать → /support». Не чаще одного раза за сессию, без всплывающих окон.
- Тексты блока — на русском, дружелюбные, без давления. Использовать слово «поддержать», а не «донат».

## Ограничения
- Не использовать FSM там, где можно обойтись callback_data.
- Все тексты — на русском, дружелюбные, без медицинского жаргона.
- Код типизирован (type hints), с docstring'ами.
- Не давать медицинских советов. При очень высоком давлении (например, ≥180/110) — вежливо предложить обратиться к врачу, без диагнозов и без критериев скорой.

- Реквизиты и любые платёжные данные — только на внешней странице, не в боте.
- Токен хранится только в переменных окружения / секрет-менеджере; в коде, конфигах и логах токена быть не должно.
- Проект распространяется под лицензией PolyForm-Noncommercial-1.0.0 (файл LICENSE в корне). В pyproject.toml указать `license = {text = "PolyForm-Noncommercial-1.0.0"}`. В README.md — раздел «Лицензия» с кратким описанием.
- Коммерческое лицензирование: Для использования в клиниках, коммерческих медицинских центрах и других организациях требуется отдельная платная лицензия. Контакт для запросов: `AUTHOR_CONTACT`.

## Требования, добавленные при уточнении (2026-11-04)

- Три измерения в день: утро, обед, вечер. Напоминания-слоты (утро/обед/вечер) + одноразовый повтор замера после приёма лекарства — автоматически после «Приняли лекарство?» → «Да» (пауза 30/60/120 мин, по умолчанию 60).
- Напоминания о лекарствах — с указанием, какие именно: список лекарств пользователя с дозировками (дозировка опциональна — «Без дозировки»); в слоте — одно сообщение «Пора измерить давление. 💊 Лекарства: …» с кнопками «Записать давление» / «Принял всё ✓» / «Частично…» / «Через 30 мин» / «Пропускаю». Настройка за 3 коротких шага (название → дозировка → когда). Приверженность в статистике («принято X из Y», только расписание слоты — кризисные препараты не входят) и CSV приёмов отдельным файлом.
- Добавление лекарства — 3 коротких шага: 1) название (свободный ввод ≤ 100 символов, подсказка «Например: Лозартан, Амлодипин»); 2) дозировка (кнопки 5/10/20/50/100 мг, «Без дозировки» и «Другое»: число + мг/мл/таб, хранится строкой); 3) «Когда принимать» (мультивыбор слотов «Утро»/«Обед»/«Вечер»/«Кризис», кнопка «Готово»). Одно лекарство в нескольких слотах — несколько записей. Слот «Кризис» — препарат на случай кризиса (давление огромное, нужно сбить): без напоминаний и вне приверженности.
- Бот многопользовательский: данные строго изолированы по telegram_id.
- Многопоточность/конкурентность: максимальная защита от гонок, двойных нажатий и повторных доставок.
- Весь код покрыт юнит-тестами (pytest, ≥ 90% строк; бизнес-логика — 100% веток; тесты конкурентности обязательны).
- Тулинг: uv + pyproject.toml. Docstrings и комментарии — по-русски.

## Напоминания: техническая реализация
- Планировщик: APScheduler 3.x, AsyncIOScheduler, SQLAlchemyJobStore (SQLite) — job'ы переживают рестарт; поллинг БД не используется.
- Инициализация: AsyncIOScheduler(timezone="UTC"). Время напоминаний пользователя хранится в его локальной зоне (users.timezone), конвертация в UTC — при создании/обновлении job'а (ловушка DST с ZoneInfo в APScheduler 3.x).
- Job defaults: coalesce=True, max_instances=1, misfire_grace_time=300.
- При старте бота: проверить reminders.next_trigger_time; если время прошло и напоминание не было отправлено — отправить одно (с кнопками), затем пересчитать next_trigger_time. Не более одного раза за день на каждый тип.
- Отмена/перенос: при нажатии «Через 30 мин» — перезаписать next_trigger_time существующей строки слота на +30 мин транзакционно; новую строку не создавать.

## Защита от дублей
- Debounce 1.5 сек на все callback-кнопки в флоу записи давления (middleware или in-memory dict); повторный тап — «Уже записываю…».
- При сохранении измерения: проверить наличие записи с тем же user_id и timestamp (округление до минуты). При совпадении — не сохранять, ответить «Это давление уже записано».

## Схема БД: уточнения
- users.reminder_time — удалить. Время напоминаний хранится только в reminders (user_id, type: 'morning'|'noon'|'evening'|'med_remeasure', local_time, next_trigger_time, enabled, last_sent_date, measurement_id).
- measurements.timestamp — DateTime(timezone=True), хранить в UTC. Границы «сегодня» и «недели» вычислять в users.timezone.
- measurements.medication_taken — Boolean, nullable (None = не спрашивали/пропустил).
- measurements.feeling — String, nullable, допустимые значения: normal, headache, weakness, other.
- users.last_support_shown_at — DATETIME NULL: футер «Поддержать» не чаще 1 раза в сутки.
- users.med_remeasure_delay — по умолчанию 60; NULL = выключено пользователем.
- DEFAULT_TIMEZONE — по умолчанию Europe/Minsk (IANA), используется, если пользователь пропустил выбор таймзоны.
- Новая таблица medications: id, user_id (FK), name (≤ 100), dosage (≤ 50, строкой, например «10 мг»; пустая строка — «без дозировки»), slot (morning|noon|evening|crisis), created_at. UNIQUE (user_id, name, slot) — одно и то же лекарство не дублируется в одном слоте.
- Новая таблица medication_logs: id, user_id (FK), medication_id (FK), timestamp (UTC), status (taken|skipped|partial), slot. Отметка действия — по одной записи на лекарство слота, одной транзакцией.
- Новая таблица measurement_medications: id, measurement_id (FK measurements.id, CASCADE), medication_id (FK medications.id, CASCADE), UNIQUE (measurement_id, medication_id). Связь записи измерения с отмеченными при «Готово» приёмами — перечень в «Истории записей» кабинета; идемпотентна, каскадно удаляется с записью или лекарством.
- Новая таблица web_users (личный кабинет): id, user_id (FK users.id, UNIQUE), email (UNIQUE), password_hash (Argon2id), created_at.

## Безопасность токена
- Токен даёт полный доступ к боту; утечка = компрометация.
- Хранится только в переменных окружения (.env в .gitignore) или в секрет-менеджере (Docker secrets, HashiCorp Vault, AWS Secrets Manager); в продакшене — переменные окружения контейнера, а не файл на диске.
- В коде, конфигах и логах токена быть не должно; не логировать ни в каких сообщениях, включая отладочные.
- Ротация: при подозрении на утечку — немедленно отозвать через @BotFather (/revoke) и выпустить новый.
- Webhook (если будет использоваться вместо long polling): валидировать заголовок X-Telegram-Bot-Api-Secret-Token. Для long polling не требуется.
- Pre-commit hooks: detect-private-key, gitleaks — чтобы случайно не закоммитить .env.

## Административная панель, удаление и бэкапы
- Ввести переменную `ADMIN_TELEGRAM_IDS` (через запятую). Команда `/admin` доступна только этим ID.
- В админке: агрегированная статистика (без личных данных), рассылка с подтверждением и `asyncio.sleep(0.05)`, ручной запуск бэкапа, статус системы.
- В настройках пользователя — кнопка «Удалить аккаунт» (двойное подтверждение). Каскадное удаление всех записей из БД и **обязательная отмена всех напоминаний в APScheduler** перед удалением пользователя.
- Обязательно реализовать модуль `services/backup.py`.
- Создание бэкапа через `VACUUM INTO` / Online Backup API.
- Верификация `PRAGMA integrity_check`, шифрование (`age`/AES-GCM) и отправка на S3.
- Retention 7 дней + 4 недели.

### Детализация инструментов админ-панели
- **Статистика БД:** DAU/WAU, общее число записей, размер БД (основной файл + WAL), популярность слотов напоминаний.
- **Бэкапы:** статус последнего бэкапа, кнопка ручного запуска, список локальных копий, скачивание последнего бэкапа прямо в чат (если < 50 МБ), статус off-site отправки.
- **Здоровье системы:** uptime, версия Python и приложения, количество активных задач в APScheduler, счетчик ошибок за 24 часа.
- **Рассылка:** превью, подтверждение, отправка с задержкой 0.05 сек, отчет о доставке/блокировках.
- **Поиск пользователя:** по ID/username. Показывает только технические данные (дата регистрации, часовой пояс, количество записей). Строгий запрет на раскрытие медицинских данных. Кнопка «Отправить тестовое сообщение».

### Логика регистрации и входа в ЛК
- При нажатии «Личный кабинет» или `/cabinet`:
  - Если пользователя нет в `web_users` → FSM-диалог запроса e-mail, создание записи (с рандомным паролем), отправка magic link.
  - Если пользователь есть → сразу отправка magic link (15 минут).
  - Если e-mail уже занят в `web_users` → ошибка и запрос другого e-mail.

## Кабинет врача и Автотесты
### Кабинет врача (Doctor Portal)
- Пациент в настройках добавляет e-mail врача (таблица `doctor_patients`).
- Кнопка «Отправить отчет» генерирует magic link для врача.
- Врач заходит по ссылке, видит Dashboard с графиком и историей пациента (только чтение).
- Врач может оставлять комментарии к записям (видны пациенту).
- Пациент может отозвать доступ в любой момент.

### Автоматическое тестирование (QA Bot)
- Скрипт на базе `pytest` + `Playwright` + `Telethon`.
- Проверяет: онбординг, запись давления, напоминания, Web UI, кабинет врача.
- Делает скриншоты каждого шага и сохраняет в `qa/reports/screenshots/`.
- Запускается в Docker-контейнере на тестовом сервере.
- Отправляет итоговый отчет (успех/провал + ссылки на скриншоты) администратору в Telegram.

### Нагрузочное тестирование (20 одновременных пользователей)
- HTTP-кабинет: Locust (`qa/locustfile.py`), 20 виртуальных пользователей — вход, дашборд, экспорт CSV за 30 дней, лекарства, профиль, настройки; учётные записи готовит `qa/seed_load_users.py`.
- Сервисный слой: pytest (`qa/test_load_burst.py`) — 20 пользователей × N конкурентных операций на файловой SQLite (WAL, busy_timeout): массовая запись, двойные нажатия, повторы замера; запуск с `LOAD_TEST=1`.
- Живой флешмоб: 20 реальных Telegram-аккаунтов вручную проходят типовой сценарий.
- Критерии приёмки: 0 ошибок 5xx и 403/429, p95 дашборда < 2 с, CSV < 3 с, нет дублей при двойных нажатиях, каждое напоминание доставлено ровно один раз.
- Только тестовый стенд: нагрузочные аккаунты и сценарии в прод-БД не применяются.

## Редактирование последней записи (2026-11-06)

- Кнопка «✏️ Изменить» в сообщении после сохранения и «✏️ Изменить последнюю» в «Дневнике за сегодня».
- Редактируются систолическое, диастолическое, пульс (клавиатурой-калькулятором или числом в чат, с «Пропустить» для пульса); заметка/самочувствие/лекарства — существующими флоу.
- «Последняя запись» — без ограничений по давности, определяется при нажатии на сервере.
- Время записи не меняется; «Пропустить» при правке очищает пульс; «Отмена» не сохраняет правку.

## Мои лекарства: изменение и удаление (2026-11-06)

- Экран «Мои лекарства»: список (строка на слот) и кнопки «Добавить», «Изменить», «Удалить», «Назад» (у пустого списка — «Добавить» и «Назад»).
- «Изменить» → выбор лекарства из списка → те же 3 шага (название → дозировка → когда): текущие значения в подсказках шагов, «Оставить как есть» на шагах названия и дозировки. Переживающие слоты обновляются на месте (история приёмов medication_logs сохраняется), снятые слоты удаляются с логами каскадом, новые добавляются. Занятое название — «Лекарство с таким названием уже есть — введите другое.»
- «Удалить» → выбор лекарства из списка → удаляется сразу, без подтверждения (тост «Лекарство удалено», список обновляется).
- Кнопка-подтверждение удаления («Удалить «…»?») убирается.

## Графики сводки: три панели, зоны АД, адаптивность (2026-11-07)

- «Сводка за период» (ЛК и кабинет врача): вместо одного графика — три панели Chart.js: «Систолическое» (canvas `bp-chart`), «Диастолическое» (`bp-chart-dia`), «Пульс» (`bp-chart-pulse`).
- Цветные зоны на панелях САД/ДАД (ESC/ESH + ВОЗ, информационно): САД — зелёная < 130, жёлтая 130–139, красная ≥ 140; ДАД — зелёная < 85, жёлтая 85–89, красная ≥ 90 мм рт. ст. Полупрозрачная заливка полос до границ графика, границы зон — горизонтальные линии. Пульс — без зон. Пороги — константы `web/cabinet/chart_zones.py`, от «цели» пользователя не зависят. Под графиками — легенда зон (цветные чипы).
- Зоны рисует собственный плагин Chart.js (`beforeDraw` + `getPixelForValue`) — новых CDN-зависимостей нет. Общий код графиков — `web/cabinet/static/bp-charts.js`, данные — JSON-острова в шаблонах (дублирование инлайн-скриптов двух шаблонов устранено).
- Адаптивность ЛК и кабинета врача: брейкпоинты 480/768/1024/1280. Панели графиков: 3 колонки (≥1024), 2+1 (768–1023), вертикально (<768); высота графиков CSS-ная (220/260/280 px), canvas без фиксированного height.
- «Личная карточка»: блок «Лекарства» — на всю ширину ряда, четыре группы по слотам приёма («Утро», «Обед», «Вечер», «Кризис»), по одному лекарству на строку (без жёстких переносов); пустые группы не показываются.
- Таблица «История записей» на экранах <768 px — карточками (подписи полей из `data-label`), без горизонтального скролла. Таблица редактирования лекарств остаётся прокручиваемой.
- Тултипы — с единицами измерения; легенды Chart.js отключены, названия панелей — заголовки над графиками.

## Лендинг: вход в ЛК и актуализация руководства (2026-11-07)

- Кнопка/ссылка «Войти в личный кабинет» → `/login` веб-кабинета (e-mail + пароль) в трёх местах лендинга: шапка (компактная призрачная кнопка рядом с «Открыть в Telegram»), финальный CTA, раздел руководства «Личный кабинет» (`#docs-cabinet`). Адаптивность шапки (бургер-меню не добавляется): <640 px — обе кнопки компактные, только иконка логотипа; 640–1023 px — название логотипа и кнопки, навигация скрыта; 1024–1279 px — иконка логотипа, навигация и кнопки; ≥1280 px — полный вид.
