# Внешний вид бота и «Крупный режим»: вопросы по деталям

Задача (2026-11-12): сделать внешний вид бота максимально удобным для пользователя и
администратора; продумать режим крупных элементов для людей с плохим зрением
(активация — в «Настройках»). Никакого кода до ответов и полного утверждения.

**Статус:** ответы на UI1–UI17 получены (2026-11-12) — зафиксированы ниже, правки
`doc/SPEC.md` и `CLAUDE.md` внесены. UI18–UI20 — дополнительные развилки, найдены при
сводке ответов; решены по ревью SPEC 2026-11-12 (все — вариант А) и закреплены ниже как
обычные правила — скобочные ссылки «(UI18)»–«(UI20)» из SPEC убраны. Дифф SPEC для 0.5.10
готов к утверждению.

Сверено с `doc/SPEC.md`: §6.1–§6.13 (экраны бота), §6.6 («Настройки»), §6.7 (кнопки
напоминаний), §8 (callback_data ≤ 64 байт, состояние в клавиатуре), §11 («Тексты и тон»),
§16.2 («Единый UI-канон кнопок» — канон веб-части; для бота канона пока нет), §13 (тесты),
§18 (админка); с кодом `bot/keyboards.py`, `bot/texts.py`, `bot/services/admin.py`.

**Как отвечать:** букву варианта (или свой) — в строку «Ответ». «Моё мнение» — только
мнение. Код не пишу до ответов и утверждения.

**Охват:** только внешний вид (тексты экранов, раскладки клавиатур, форматы вывода).
Функции и сценарии §6 не меняются — новых возможностей не добавляем (правило SPEC).
«Крупный режим» — только рендер: данные, валидация, callback_data и обработчики те же.

## 0. Рамки платформы (в них проектируем)

Что Telegram **не даёт** боту менять — это важно, чтобы «крупный режим» обещал реальное:

- **Кегль текста и высота кнопок** задаёт клиент Telegram (настройки шрифта в Telegram
  Desktop / iOS / Android). Бот их не меняет. Поэтому «крупный» = крупные **элементы
  управления и раскладка**: широкие кнопки, меньше объектов на экран, акценты жирным,
  укрупнённые картинки — а не увеличенный шрифт.
- **Ширина inline-кнопки** — доля строки: 1 кнопка в ряду ≈ вся ширина экрана (максимальная
  зона нажатия), 2 в ряду ≈ половина, 3 ≈ треть. Это главный «рычаг» крупного режима.
- Ряд кнопок — не больше 8; `callback_data` ≤ 64 байт (§8); кнопки — только inline
  (принцип «редактируем сообщение», §6.2); ReplyKeyboard не используем.
- Жирный/курсив — только через parse mode; сейчас бот шлёт plain text (исключение —
  Markdown в рассылке админки, `bot/services/admin.py`). См. UI5.

## 1. Визуальный язык бота (для всех пользователей)

Сейчас экраны оформлены по-разному: у главного меню нет заголовка, у «Напоминаний» —
заголовок-текст, у сводки — «✅ Записано», у деника — «Дневник за сегодня». Предложение —
закрепить единый шаблон (по духу «Единого UI-канона кнопок» §16.2, но для бота):

```
[эмодзи] Заголовок экрана        ← первая строка каждого экрана меню
[тело: данные, статусы, подсказки]
[кнопки: сначала действия, потом навигация]
```

- Заголовок — у всех экранов меню и настроек: «📊 Статистика», «⚙️ Настройки»,
  «☀️ Напоминания», «📖 Дневник за сегодня», «📅 Визиты и анализы», «👤 Мои данные» и т. д.
  У шагов ввода («Систолическое (верхнее)?») заголовок-«шапка» не нужен — вопрос сам по себе.
- Навигация внизу клавиатуры: «Назад» — уровень выше, «В меню» — главное меню (подписи
  канонические, уже в `texts.py`).
- Значения давления: в списках — компактно «135/85, пульс 72»; в сводках — по строке на
  поле (см. UI4).
- Тон и словарь — прежние (§11): по-русски, коротко, «измерение», «поддержать».

Наброски «обычный / крупный» для ключевых экранов — ниже, в разделе 2.

## 2. «Крупный режим»: наброски

Активация — переключатель в «Настройках» (решено задачей). Предлагаемый вид строки
(канон «строка-состояние», как «⏸ Пауза: нет» в «Напоминаниях»):

```
⚙️ Настройки
👁 Крупный режим: выкл        ← кнопка-переключатель, вкл/выкл
Целевые значения
Напоминания
…
```

### 2.1. Клавиатура-калькулятор (§6.3)

Обычный (как сейчас, 3 колонки):

```
Систолическое (верхнее)?
Введено: 12
Можно также написать число сообщением.

[1] [2] [3]
[4] [5] [6]
[7] [8] [9]
[C] [0] [⌫]
[Готово] [Пропустить]
[Отмена]
```

Крупный (2 колонки — каждая кнопка вдвое шире):

```
Систолическое (верхнее)?
Введено: 12
Можно также написать число сообщением.

[  1  ] [  2  ]
[  3  ] [  4  ]
[  5  ] [  6  ]
[  7  ] [  8  ]
[  9  ] [  0  ]
[    C    ] [    ⌫    ]
[        Готово        ]
[     Пропустить       ]
[        Отмена        ]
```

### 2.2. Сводка сохранённой записи (§6.3)

Обычный:

```
✅ Записано
Систолическое: 135
Диастолическое: 85
Пульс: 72
```

Крупный (те же строки, значения — жирным; формат сводки — UI4):

```
✅ Записано

Систолическое: 135        ← 135 жирным
Диастолическое: 85
Пульс: 72
```

Кнопки сводки и в обычном режиме — по одной в строке (как сейчас).

### 2.3. «Дневник за сегодня» (§6.4)

Обычный (одна строка — запись):

```
📖 Дневник за сегодня
08:15 — 135/85, пульс 72 · лекарство: да · норма
12:40 — 128/80
Всего записей: 2
💊 Лекарства: утро ✓ · обед — ещё не отмечено
```

Крупный (одна запись — блок, значения жирным):

```
📖 Дневник за сегодня

08:15
135/85 · пульс 72
лекарство: да · норма

12:40
128/80

Всего записей: 2
💊 Лекарства: утро ✓ · обед — ещё не отмечено
```

### 2.4. Напоминание слота (§6.7)

Обычный (кнопки в 1–2 ряда, как сейчас — «Да»/«Нет»-пары и т. п. в ряд):

```
Пора измерить давление ☀️
💊 Лекарства: Лозартан 50 мг, Амлодипин 5 мг

[Записать давление] [Принял всё ✓]
[Отметить принятые] [Через 30 мин]
[Пропускаю сегодня]
```

Крупный (все кнопки — по одной в строке):

```
Пора измерить давление ☀️
💊 Лекарства: Лозартан 50 мг, Амлодипин 5 мг

[      Записать давление      ]
[        Принял всё ✓         ]
[      Отметить принятые      ]
[        Через 30 мин         ]
[       Пропускаю сегодня     ]
```

### 2.5. Главное меню (§6.2)

В обоих режимах — по одной кнопке в строке (уже так): меню не меняется, крупный режим
его не ухудшает. Пункты главного меню — без изменений.

## 3. Вопросы

### A. Визуальный язык (все пользователи)

#### UI1. Единый шаблон экрана

Закрепить канон (шапка «[эмодзи] Заголовок», тело, кнопки: действия → навигация «Назад» /
«В меню») для всех экранов меню, настроек и сценариев?

- **А** — да, канон для всех экранов бота; заголовки добавляются, где их нет (главное меню —
  «🏠 Главное меню» или без заголовка — уточните); тесты `test_texts.py` проверяют состав.
- **Б** — канон только для основных экранов (меню, статистика, настройки, дневник),
  мелкие шаги ввода не трогаем.
- **В** — не трогать, оставить как есть.

**Моё мнение:** А — единообразие и предсказуемость; главному меню оставить без заголовка
(само по себе понятно), остальным добавить шапки.

**Ответ:** А — канон для всех экранов; **главное меню — без заголовка**; шаги ввода
(«Систолическое (верхнее)?») — без шапки: вопрос и есть заголовок. Словарь канонических
шапок (для тестов `test_texts.py`) — в §11 «Канон внешнего вида бота». 0.5.10.

#### UI2. Стиль эмодзи

- **А** — умеренный (как сейчас): эмодзи в заголовках экранов и статусах (✅, 💊, 📅,
  🟢/🟡/🔴), в кнопках — точечно (✏️, 📅, 💊, 📊, ➕); без эмодзи в каждой строке.
- **Б** — минимум: эмодзи только в статусах (✅, зоны 🟢/🟡/🔴), кнопки текстовые.
- **В** — насыщеннее: эмодзи у каждого пункта меню и каждой строки данных.

**Моё мнение:** А — текущий баланс читаем; В перегружает и без того плотные экраны.

**Ответ:** А — умеренный стиль эмодзи; правило дословно — в §11: «Эмодзи: в заголовках
экранов, статусах (✅, 💊, 📅, 🟢/🟡/🔴), в кнопках точечно (✏️, 📅, 💊, 📊, ➕); не в каждой
строке данных». 0.5.10.

#### UI3. Раскладка кнопок в обычном режиме

Сейчас смешанно: главное меню и действия — по одной кнопке в строке; «Да»/«Нет»,
«Готово»/«Пропустить» — парами в ряд.

- **А** — везде по одной кнопке в строке (и пары «Да»/«Нет» тоже).
- **Б** — зафиксировать текущий смешанный канон: пары в ряд только для коротких
  альтернатив («Да»/«Нет», «Готово»/«Пропустить»/«Отмена», «Принять»/«Отклонить»),
  всё остальное — по одной.
- **В** — больше пар («Назад»+«В меню» в ряд, «7 дней»+«30 дней» в ряд и т. п.).

**Моё мнение:** Б — пары альтернатив экономят высоту и не мешают; «Назад»/«В меню»
раздельно — они не альтернативы. В крупном режиме пары разъезжаются по строкам (§2.4).

**Ответ:** Б — пары в ряд только для коротких альтернатив (перечень пар — в §11): «Да» /
«Нет», «Готово» / «Пропустить», «Мужской» / «Женский», «Принять» / «Отклонить»,
«7 дней» / «30 дней»; слот-сообщение — «Записать давление» / «Принял всё ✓» и
«Отметить принятые» / «Через 30 мин», «Пропускаю сегодня» — отдельно; режим «Только
лекарства» — «Принял всё ✓» / «Отметить принятые» (по 3 строки, ревью 2026-11-12); повтор
замера — «Записать сейчас» / «Через 30 мин» / «Больше не напоминать» — 2+1; уведомление о
визите — «✓ Помню» / «Перенести» — пара. Всё остальное — по одной в строке; в крупном
режиме пары разъезжаются по строкам. **Исключение** (ревью 2026-11-12): калькулятор
(§6.3), календарь (§6.5, §6.13) и сетки времени/целевых значений (§6.1, §6.6, §6.13)
держат свою раскладку (3 колонки в обычном режиме, 2 — в крупном; сетка времени — 3–4
кнопки в ряд) и правилу «по одной в строке» не подчиняются. 0.5.10. (Пара «Отменить визит»
/ «📄 Отчёт для врача» — UI20.)

#### UI4. Формат сводки «✅ Записано» (и архивной «✅ Записано за …»)

- **А** — как сейчас, по строке на поле («Систолическое: 135»), в обоих режимах без
  изменений.
- **Б** — обычный режим — компактно «135/85, пульс 72» одной строкой; крупный — по строке
  на поле.
- **В** — везде по строке на поле; в крупном режиме значения жирным (набросок 2.2).

**Моё мнение:** В — один формат для тестов и поддержки, различие режимов — только акцент.

**Ответ:** В — по строке на поле в обоих режимах; в крупном режиме значения жирным
(§6.3, §6.10, §11). Списки (дневник, средние по дням) — блоками в крупном (набросок 2.3).
0.5.10.

#### UI5. Жирный текст (parse mode)

Сейчас бот шлёт plain text. Жирные значения — главный «крупный» акцент текста, но parse
mode требует экранирования пользовательского текста (заметки, названия лекарств, ФИО).

- **А** — ввести HTML везде: заголовки и значения жирным во всех экранах; пользовательский
  текст экранируется; тесты текстов переписываются под HTML.
- **Б** — HTML точечно: только сообщения с акцентами (сводки, дневник, крупный режим);
  остальное — plain text; экранирование пользовательского текста обязательно.
- **В** — plain text без жирного; крупный режим достигается только раскладкой.

**Моё мнение:** Б — жирный там, где он несёт смысл (цифры), минимум площади для ошибок
экранирования; А — дорого и рискованно без выигрыша на шагах ввода.

**Ответ:** Б — HTML точечно (§11): шапки экранов — `<b>{эмодзи} Заголовок</b>` всегда
(оба режима); значения в `<b>` — в крупном режиме везде, где они есть (сводки, дневник,
списки, уведомления о визитах и слотах); обычный режим — plain text. Пользовательский
текст (заметки, названия лекарств, ФИО, текст рассылки) в HTML-сообщениях экранируется
(`html.escape`). Тесты: `test_texts.py` — шапки в `<b>`; `test_services_admin.py` —
рассылка с HTML безопасна. 0.5.10.

### B. «Крупный режим»

#### UI6. Состав режима (один переключатель или несколько)

Что включает «Крупный режим» одним переключателем:

1. кнопки — по одной в строке везде (включая пары «Да»/«Нет», «Готово»/«Отмена»);
2. калькулятор — 2 колонки вместо 3 (набросок 2.1);
3. списки — блоками (одна запись — блок, набросок 2.3) и пагинация длинных (UI13);
4. сводки — значения жирным (UI4/UI5);
5. гистограмма — с крупными подписями (UI11).

- **А** — всё пакетом, один переключатель «👁 Крупный режим».
- **Б** — только кнопки и калькулятор (пункты 1–2), остальное не трогать.
- **В** — раздельные переключатели («Крупные кнопки» / «Крупные списки» / …).

**Моё мнение:** А — один переключатель, целевая аудитория не будет разбираться в трёх;
В — ложная точность.

**Ответ:** А — всё пакетом, один переключатель «👁 Крупный режим» (§6.6). 0.5.10.

#### UI7. Активация и подсказка о режиме

Канон — переключатель первым пунктом «Настроек» (строка-состояние «👁 Крупный режим:
вкл/выкл», нажатие переключает и перерисовывает экран). Дополнительно:

- **А** — только «Настройки», больше нигде не предлагаем.
- **Б** — + шаг в онбординге (§6.1): экран «Как вам удобнее смотреть?» — «Обычный» /
  «Крупный» + «Пропустить» (как у всех шагов); активация всё равно остаётся и в
  «Настройках».
- **В** — + одноразовая мягкая подсказка после онбординга: «Если мелко — включите крупный
  режим в «Настройках»» + кнопка «Включить» / «Не сейчас».

**Моё мнение:** Б — целевая аудитория узнаёт о режиме сразу, а не найдёт его месяцем
позже; шаг — один экран с «Пропустить», трения почти нет.

**Ответ:** Б — шаг онбординга **после «Приветствия», до «Часового пояса»** (порядок
важен: пользователь выбирает режим и весь дальнейший онбординг идёт в нём): «Как вам
удобнее смотреть?» — «Обычный» (`onb:ui:0`) / «Крупный» (`onb:ui:1`) / «Пропустить»
(`onb:ui:skip` = обычный). «Крупный» перерисовывает этот же экран крупным (демонстрация),
кнопка «Крупный» помечается «✓». Существующим пользователям шаг не показывается
(онбординг не перезапускается) — они найдут переключатель в «Настройках»
(`set:ui:0` / `set:ui:1`). 0.5.10.

#### UI8. Хранение настройки (схема БД, поколение 9)

- **А** — `users.ui_large BOOLEAN NOT NULL DEFAULT 0` («0» — обычный режим); миграция —
  `ALTER TABLE users ADD COLUMN`, как `followup_enabled` (поколение 7).
- **Б** — `users.ui_mode TEXT NOT NULL DEFAULT 'standard' CHECK IN ('standard','large')` —
  запас на будущие режимы отображения.

**Моё мнение:** А — режимов два, BOOLEAN читается однозначно; расширение потом — та же
`ALTER TABLE`. Б оправдан, только если уже известен третий режим — его нет.

**Ответ:** А — `users.ui_large BOOLEAN NOT NULL DEFAULT 0`; миграция —
`ALTER TABLE users ADD COLUMN`; **поколение 9** (0.5.10). 0.5.10.

#### UI9. Область действия настройки

- **А** — только бот: `users.ui_large` меняет рендер бота; веб-кабинет не трогаем
  (у него свой канон §16.2 и своя тема).
- **Б** — бот и личный кабинет одной настройкой: размер шрифта и кнопок веб-части тоже
  переключаются (отдельная работа в `web/cabinet`).

**Моё мнение:** А — задача про бота; веб-часть с её Tailwind-каноном — отдельной задачей,
настройку от него не запираем (поле общее, рендер ЛК подключит себя).

**Ответ:** А — только бот; в ЛК не подключён (отдельной задачей). Поле `users.ui_large` —
общее, веб-рендер может его использовать позже (оговорка в §16.2). 0.5.10.

#### UI10. Напоминания и уведомления в крупном режиме

Кнопки слот-сообщений, повторов, «Не забыли…», уведомлений о визитах — перестраиваются по
правилам крупного режима (по одной в строке, набросок 2.4)?

- **А** — да, все сообщения бота рендерятся по режиму пользователя.
- **Б** — нет, уведомления одинаковые для всех, крупный режим действует только на экраны
