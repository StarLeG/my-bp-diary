# Бот: галочки «уже принятых сегодня» в мультивыборе лекарств — вопросы перед планом

Жалоба: при новой записи давления → «Приняли лекарство?» → «Да» в списке «Какие лекарства приняли?» уже стоят «✓» от прошлых выборов.

Сверено с `doc/SPEC.md` §6.3, §4.5, §4.11, §7.2 и кодом `bot/handlers/measure.py` (`cb_med_yes`, `cb_med_pick`, `cb_med_done`), `bot/keyboards.py` (`intake_meds_kb`).

**Как отвечать:** впишите букву варианта (или свой вариант) в строку «Ответ». «Моё мнение» — только мнение. Код не пишу, пока нет ответов.

---

## Что происходит сейчас

- Это не случайность, а текущее правило SPEC §6.3: «„✓“ — у отмеченных **и уже отмеченных за сегодня**». `cb_med_yes` заранее кладёт в выбор все лекарства с отметкой в журнале за локальные сутки (`logged_intake_ids_today`: мультивыбор, «Принял всё ✓» по напоминанию, «Пропускаю» — любой статус).
- **Побочный эффект.** «Готово» отправляет весь набор галочек — и заранее отмеченные тоже. Журнал второй строки не создаёт (дедуп за сутки), а **связь с новой записью создаёт** (`measurement_medications`). В итоге у каждой следующей записи за день в «Истории записей» кабинета — «Принято: Канверс плюс 16/12,5, ЛерканНАН 10 мг», хотя их принимали утром, а не при этом замере. Снять галочку можно, но это лишние нажатия на каждой записи.
- Отметка «Пропускаю» по напоминанию тоже даёт «✓» — хотя приём пропущен.

---

### B1. Как показывать «уже принятые сегодня»

- **А** — выбор открывается **пустым**; у принятых сегодня — пометка в подписи, без галочки: «Канверс плюс 16/12,5 · утро · сегодня ✓». Нажатие отмечает его для этой записи как обычно. «Готово» связывает с записью только то, что отмечено сейчас.
- **Б** — выбор открывается пустым, без всяких пометок о принятом сегодня.
- **В** — как сейчас (заранее отмечены), но при «Готово» заранее отмеченные и не тронутые пользователем к записи не привязываются. Видимая галочка и результат расходятся — путает.

**Моё мнение:** А — пользователь видит, что уже пил сегодня (защита от двойной дозы), но запись получает только выбранное сейчас.

### B3. Уже созданные лишние связи на проде

**Контекст.** У записей, сохранённых с заранее отмеченными галочками, в истории есть «Принято: …» с лекарствами, принятыми раньше. Отличить их от выбранных намеренно по данным нельзя: и те и другие — одинаковые строки `measurement_medications`.

## Ответы (2026-11-08)

- **B1 — А.** Выбор открывается пустым; у принятых сегодня — пометка «· сегодня ✓» без галочки; привязка к записи — только осознанным действием пользователя.
- **B2 — А.** Пометка — только по `status='taken'`: «Пропускаю» и «Частично» — не «принято».
- **B3 — А.** Уже созданные связи не трогаем: без флага «отмечено пользователем» случайную связь не отличить от намеренной; лишнее снимается правкой ✏️ в кабинете.

## Допущения на подтверждение

1. Кабинет не меняется: там предотметка по слоту времени (§16.2), а не по журналу за сутки.
2. Нажатие на лекарство «принятое сегодня» отмечает его для этой записи; журнал второй строки за сутки не создаёт (дедуп §7.2), связь создаёт — как сейчас.
3. «Готово» без единой галочки — как сейчас: всплывающее «Отметьте, что приняли» (экран не меняется).
4. Это исправление поведения — версия PATCH (0.4.7).

## Черновой план

1. SPEC §6.3 — новое правило по ответам.
2. `cb_med_yes`: выбор пустой; набор «принято сегодня» — отдельно, для подписи (B1, B2).
3. `intake_meds_kb`: пометка у принятых сегодня; `cb_med_pick` — та же пометка при перерисовке.
4. Тесты: выбор открывается пустым; пометка; «Готово» связывает только отмеченное; «Пропускаю» — по B2; повторное «Готово» идемпотентно.
