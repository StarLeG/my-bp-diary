# Кнопка «Записать давление» — полный функционал

Справка по флоу записи давления в боте. Источник истины — `doc/SPEC.md` (§6.3 — запись,
§6.10 — архивные записи, §7.2 — конкурентность, §8 — FSM и callback_data, §9 — валидация);
здесь — как это устроено в коде и как ведёт себя кнопка от нажатия до опциональных шагов.

Код: `bot/handlers/measure.py` (хендлеры флоу), `bot/keyboards.py` (клавиатуры),
`bot/texts.py` (все тексты), `bot/schemas.py` (валидация), `bot/services/measurements.py`
(записи), `bot/services/medications.py` (журнал приёмов и связи),
`bot/services/reminders.py` (повторный замер), `bot/middlewares.py` (дебаунс).

---

## 1. Точки входа

Кнопка запускает один и тот же числовой поток (систолическое → диастолическое → пульс →
сохранение). Вход определяет только контекст: новая запись, правка или ответ на напоминание.

| Callback | Откуда кнопка | Поведение |
|---|---|---|
| `menu:measure` | Главное меню «Записать давление»; «Дневник за сегодня» при пустом списке | Новая запись текущим моментом |
| `rem:write:{slot}:{д}` | «Записать давление» в напоминании слота (`slot_message_kb`) | Новая запись; плюс `reminders.cancel_followup(user.id, slot)` — повтор «если не ответил» отменяется (0.5.6) |
| `rem:write` | То же, старый формат без слота (до 0.5.6) | Новая запись, без отмены followup |
| `rem:now` | «Записать сейчас» в напоминании повторного замера (`remeasure_kb`) | Новая запись текущим моментом |
| `m:edit` | «✏️ Изменить» в сводке; «✏️ Изменить последнюю» в «Дневнике за сегодня» | Правка последней записи (§7) |
| `set:archive:add`, `m:arch:more` | «Настройки» → «Архивные записи»; «➕ Ещё запись» | Тот же числовой поток с явным моментом измерения (§9) |

Обработчик начала — `cb_measure_begin` (`bot/handlers/measure.py`):
1. пользователь берётся get-or-create (`get_or_create_user`), читается `ui_large`;
2. у `rem:write:{slot}:{д}` проверяется, что `{slot}` ∈ `SLOT_ORDER` (`morning`/`noon`/`evening`),
   и отменяется followup слота;
3. прошлый черновик сбрасывается (`state.clear()`), ставится `MeasureInput.sys_input`,
   буфер набора пуст (`M_BUF = ""`);
4. показывается экран шага 1.

Повторное «Записать давление» посреди ввода перезаписывает черновик заново — второй
параллельный поток не плодится (§7.2).

## 2. Состояния и черновик (FSM)

FSM — только для коротких цепочек и свободного ввода; всё, что выбирается кнопками, живёт
в `callback_data` (§8). Черновик измерения — в FSM-storage (ключ по пользователю), не в БД.

Состояния (`MeasureInput` в `bot/handlers/measure.py`):

| Состояние | Что ждём |
|---|---|
| `sys_input` | систолическое (калькулятор или число в чат) |
| `dia_input` | диастолическое |
| `pulse_input` | пульс или «Пропустить» |
| `note_input` | текст заметки |
| `feeling_other` | текст «Другое» (самочувствие) |

Для архива дополнительно `ArchiveInput.date` / `ArchiveInput.time` / `ArchiveInput.quick` (§9).

Ключи черновика в FSM:

| Ключ | Назначение |
|---|---|
| `m_sys`, `m_dia`, `m_pulse` | подтверждённые значения шагов (`m_pulse = None` — пропущен) |
| `m_buf` | буфер набора калькулятора (строка ≤ 3 цифр) |
| `m_id` | id сохранённой записи — к ней привязываются все опциональные шаги |
| `m_edit_id` | id редактируемой записи (режим правки; канон «цель фиксируется при входе») |
| `m_med_checked` | отмеченные id мультивыбора «Какие лекарства приняли?» |
| `m_med_taken_today` | id приёмов, принятых за сегодня, — для пометки «· сегодня ✓» |
| `m_arch_ts` | момент архивной записи, ISO 8601 UTC; **наличие ключа = режим архива** |
| `m_arch_label` | момент строкой для сводки («12.03.2025, 08:00») |
| `arch_date` | дата шага «Когда?» до выбора времени |

Режим сохранения определяется ключами: нет `m_edit_id` и нет `m_arch_ts` — INSERT текущим
моментом; есть `m_edit_id` — UPDATE; есть `m_arch_ts` — INSERT с указанным `timestamp`.

## 3. Клавиатура-калькулятор

### 3.1 Экран шага

Текст экрана (`texts.fmt_keypad_prompt`) — три части:

```
Систолическое (верхнее)?

Введено: 12
Можно также написать число сообщением.
```

«Введено: —» — буфер пуст. Экран **редактируется** (`edit_message_text`) на каждое нажатие
кнопки; ответы на свободный ввод в чат приходят новыми сообщениями.

Порядок шагов (`_advance`): `sys_input` → `dia_input` → `pulse_input` → сохранение.
Переход — только после подтверждённого значения («Готово» или число в чат).

### 3.2 Кнопки и callback'и

| Кнопка | Callback | Действие |
|---|---|---|
| `0`…`9` | `m:key:{цифра}` | добавить цифру в буфер |
| `C` | `m:key:clear` | очистить буфер |
| `⌫` | `m:key:bksp` | стереть последнюю цифру |
| `Готово` | `m:key:ok` | подтвердить значение и перейти дальше |
| `Пропустить` | `m:key:skip` | только шаг пульса: значение `None`, сразу сохранение |
| `Отмена` | `m:cancel` | сброс черновика и FSM, главное меню (правка не сохраняется) |

Буфер (`_buf_add`): не более 3 цифр; ведущие нули схлопываются (`"0" + "5"` → `5`,
`"00" + "5"` → `5`); нажатие, переполняющее буфер («260» + «5»), игнорируется.

Поведение «Готово» (`m:key:ok`):
- пустой буфер — тост «Введите число», экран не меняется;
- значение вне диапазона или нарушение пары — тост с ошибкой валидации (§4), экран не меняется;
- успех — следующий шаг калькулятора или (с пульса) сохранение.

«Пропустить» (`m:key:skip`) существует только на шаге пульса; в иных состояниях кнопка
не показывается, а её (устаревший) вызов возвращает в главное меню. Пульс при этом
полностью очищается — и при правке тоже («Пропустить» = пустой пульс, полная перезапись).

### 3.3 Свободный ввод числом в чат

Любое сообщение в состояниях `sys_input`/`dia_input`/`pulse_input` — попытка сразу
подтвердить значение (`_msg_value` → `_confirm_value`):
- успех — следующий шаг (экран приходит новым сообщением);
- ошибка — короткое сообщение с текстом ошибки и повтор ввода.

Не-число («12.5», «120/80», «сто двадцать») — «Нужно целое число от … до …» (§4).

### 3.4 Раскладки: обычный и крупный режим

Крупный режим (`users.ui_large=1`, §6.6, канон §11) — только рендер, данные и валидация
те же.

- **Обычный** (`keypad_kb`, `large=False`): как калькулятор — `7 8 9` / `4 5 6` / `1 2 3` /
  `C 0 ⌫`; затем «Готово» (с «Пропустить» рядом на пульсе), внизу «Отмена».
- **Крупный** (`large=True`): цифры в 2 колонки — `1 2` / `3 4` / `5 6` / `7 8` / `9 0`;
  `C` / `⌫` рядом; «Готово», «Пропустить», «Отмена» — каждая отдельной строкой.

## 4. Валидация

Pydantic-схемы (`bot/schemas.py`), те же ограничения продублированы CHECK в `measurements`
(§4.2). Сообщения об ошибках — короткие и человеческие; при ошибке экран не меняется
(тост) или остаётся с повтором ввода (свободный ввод).

| Поле | Правило | Сообщение об ошибке |
|---|---|---|
| систолическое | целое 70…260 | «Нужно целое число от 70 до 260» / «Нужно систолическое от 70 до 260, а получилось N» |
| диастолическое | целое 40…160, строго ниже систолического | «Нужно диастолическое от 40 до 160, а получилось N»; пара: «Диастолическое (нижнее) должно быть ниже систолического (верхнего) — проверьте цифры.» |
| пульс | целое 30…220 или «Пропустить» | «Нужно пульс от 30 до 220, а получилось N» |
| заметка | строка 1…500 (trim) | «Заметка не может быть пустой» / слишком длинная |

Пара давлений проверяется при подтверждении диастолического; минимальная разница
(пульсовое давление) не ограничивается.

## 5. Сохранение (`_save`)

Сохранение происходит сразу после шага пульса (или в конце архивного/быстрого ввода).

Порядок (§7.2): сначала `session.commit()` записи, FSM обновляется после; ничего
«человеческого» (отправка в Telegram) внутри транзакции нет.

- **Новая запись** — `save_measurement`: `INSERT … SELECT … WHERE NOT EXISTS` под общим
  asyncio-локом сохранений. Дубль за ту же минуту (`DEDUP_WINDOW = 1 мин`, `user_id` +
  `timestamp`) → `DuplicateMeasurementError` → «Это давление уже записано» + кнопка
  «В меню», черновик очищается. Защищает и от двойного нажатия, и от гонки двух сохранений.
- **Правка** (`m_edit_id`) — `update_measurement_values`: один явный `UPDATE` всех трёх
  полей (систолическое, диастолическое, пульс) по `id` с проверкой владельца. Время записи
  не меняется, дедуп-проверка не применяется. Запись исчезла между входом в правку и
  сохранением — «Такой записи нет».
- **Архив** (`m_arch_ts`) — INSERT с указанным `timestamp` (дедуп за минуту действует).

Затем `m_id` = id записи и экран сводки. Если это не архив и (систолическое ≥ 180 или
диастолическое ≥ 110) — в конец сообщения добавляется строка «Эти значения стоит обсудить
с врачом на ближайшем приёме.» Без диагнозов и критериев скорой; для архивных записей
строка не показывается (данные исторические).

## 6. Сводка и опциональные шаги

### 6.1 Экран сводки

```
✅ Записано
Систолическое: 135
Диастолическое: 85
Пульс: 72
```

Без пульса — «Пульс: —». При правке — «✅ Обновлено», при архиве — «✅ Записано за
12.03.2025, 08:00». В крупном режиме значения — `<b>`, после шапки пустая строка
(parse mode — HTML точечно, только для крупного).

Кнопки (`saved_kb`, по одной в строке в обоих режимах):

| Кнопка | Callback | Дальше |
|---|---|---|
| ✏️ Изменить | `m:edit` | правка последней записи (§7) |
| Добавить заметку | `m:note` | свободный ввод заметки |
| Приняли лекарство? | `m:med` | «Да» / «Нет» |
| Самочувствие | `m:feeling` | варианты самочувствия |
| В меню | `menu:back` | главное меню |

У архивной сводки (`archive_saved_kb`) кнопки свои (`m:arch:*`) и вместо «В меню» —
«➕ Ещё запись» (`m:arch:more`) + «В меню» (`m:arch:menu`). Все опциональные шаги привязаны
к `m_id` только что сохранённой записи, а не к «последней записи пользователя» — гонка
«два измерения подряд» ничего не перепутает.

Все опциональные шаги — только по нажатию, ничего не навязывается.

### 6.2 Заметка

`m:note` (или `m:arch:note`) → «Напишите заметку (до 500 символов).» + кнопка «Отмена»
(`m:cancel`). Сообщение в чат — заметка (`add_note`, валидация 1…500); ответ —
«Заметка сохранена» + кнопки сводки. Ошибка валидации — текст ошибки и повтор ввода.

### 6.3 «Приняли лекарство?»

`m:med` (у архива — `m:arch:med`) → экран «Приняли лекарство?» с парой «Да» (`m:med:yes`) /
«Нет» (`m:med:no`) и «В меню». Значение пишется в `measurements.medication_taken`:
TRUE / FALSE / NULL (не отмечал). Пара «Да»/«Нет» — в ряд (обычный режим) или по одной
в строке (крупный).

**«Нет»** — флаг FALSE, возврат к сводке.

**«Да»** — флаг TRUE, затем две ветки:

1. **Повторный замер.** Если задан `users.med_remeasure_delay` («Повтор после лекарства»,
   по умолчанию 60 минут) — `RemindersService.ensure_remeasure(user.id, measurement_id, delay)`:
   одноразовый job `med_remeasure`, идемпотентно по id записи (двойное «Да» второй job не
   плодит). Экран: «Напомню повторить измерение через 60 минут.» + кнопка «Не надо»
   (`m:noremeasure:{id}`). Если задержка выключена — «Повтор измерения после лекарства
   выключен — включите в настройках, если нужен.» + кнопки сводки.
2. **Какие лекарства приняли?** Если у пользователя настроены лекарства (`medications`) —
   мультивыбор (§6.4). При запланированном повторе он остаётся отдельным экраном, а
   мультивыбор приходит следующим сообщением; без повтора мультивыбор редактирует то же
   сообщение.

После «Да», когда лекарства ещё не добавлены и это первая запись с флагом «Да»
(`medication_taken_count == 1`), один раз мягко спрашивается новым сообщением:
«Напоминать, какие лекарства принимать?» + «Добавить» (`med:add`) / «Не сейчас»
(`m:medask:dismiss` → «Хорошо. Добавить лекарства можно позже в настройках.»).

**У архива** (`m:arch:med:yes` / `m:arch:med:no`) — только исторический флаг: повторный
замер не планируется, мультивыбор лекарств и `medication_logs` не создаются.

### 6.4 Мультивыбор «Какие лекарства приняли?»

Клавиатура `intake_meds_kb`: строка-кнопка на каждый приём пользователя («✓ Лозартан
50 мг · утро», `fmt_intake_item`), внизу «Готово» (`m:med:done`) и «Отмена» (`m:med:cancel`).

- Выбор открывается **пустым**; «✓ » — только у отмеченных в этом выборе (переключение
  `m:med:pick:{id}`, галочка живёт в подписи кнопки, состояние — `m_med_checked`).
- У приёмов, уже принятых за текущие локальные сутки (`medication_logs` со статусом
  `taken`; «Пропускаю» и «Частично» не считаются) — пометка « · сегодня ✓» в конце
  подписи, **без галочки** (`m_med_taken_today`, `taken_intake_ids_today`). Нажатие
  отмечает такой приём для этой записи как обычно.
- Чужой или удалённый id в `m:med:pick:{id}` проверяется по владельцу и мягко
  отклоняется: тост «Такой записи нет».
- «Готово» — `record_manual_intake`: по одной записи `medication_logs` (`status='taken'`,
  слот — из строки лекарства) на каждый отмечен приём + связи `measurement_medications`
  с записью (перечень для «Истории записей» кабинета, §4.11/§16.2) — **одним** захватом
  лока приёмов и одной транзакцией. Пустой выбор — тост «Отметьте, что приняли»; повторное
  «Готово» за те же локальные сутки новые записи и связи не создаёт (идемпотентно, §7.2).
  Ответ — «💊 Принято: Лозартан 50 мг, Амлодипин 5 мг» + кнопки сводки.
- «Отмена» — назад к сводке без записей.
- С записью связывается **только** то, что отмечено в этом выборе.

### 6.5 Повторный замер и «Не надо»

Кнопка «Не надо» (`m:noremeasure:{id}`, id — записи измерения) — `cancel_remeasure_for_measurement`:
активный повтор записи удаляется, job снимается; проверка владельца в сервисе. Ответ —
«Хорошо, повторно напоминать не буду.» + кнопки сводки. Повторное нажатие и чужой id —
идемпотентное подтверждение без чужих данных.

Когда job повтора срабатывает, пользователь получает напоминание «Прошло время после
лекарства — пора повторить измерение 🌡» с кнопками `remeasure_kb`: «Записать сейчас»
(`rem:now` → тот же флоу новой записи), «Через 30 мин» (`rem:snooze:{id}`), «Больше не
напоминать» (`rem:off:{id}`).

### 6.6 Самочувствие

`m:feeling` (у архива — `m:arch:feel`) → «Как самочувствие?» + варианты:

| Кнопка | Callback | Сохранение |
|---|---|---|
| Норма | `m:feeling:normal` | `feeling='normal'` |
| Головная боль | `m:feeling:headache` | `feeling='headache'` |
| Слабость | `m:feeling:weakness` | `feeling='weakness'` |
| Другое | `m:feeling:other` | свободный текст → в `note` |

Сетка 2×2 (обычный режим, канон UI3) или по одной в строке (крупный). «Другое» →
«Коротко опишите самочувствие — сохраню в заметку.» + «Отмена»; текст дописывается в
`note` записи (к существующей заметке через перевод строки), ответ — «Заметка сохранена»
+ кнопки сводки. Любой другой выбор сразу возвращает к сводке.

## 7. Правка последней записи («✏️ Изменить»)

`m:edit` (обработчик `cb_edit_begin`):

1. «Последняя запись» резолвится **на сервере** (`get_latest_measurement`: по `timestamp`
   DESC, при равном времени — по `id` DESC, строго по `user_id`). Id в `callback_data`
   не передаётся. Записей нет — тост «Такой записи нет».
2. Прошлый черновик сбрасывается; цель правки фиксируется: `m_edit_id = m_id = id записи`.
3. Дальше — те же шаги калькулятора и та же валидация, что при вводе, включая «Пропустить»
   на пульсе (полная перезапись: пульс становится пустым).
4. Сохранение — UPDATE трёх значений (`update_measurement_values`): «✅ Обновлено» + та же
   сводка + те же кнопки опциональных шагов. Время записи не меняется; дубль-проверка не
   применяется. При новых значениях ≥ 180/110 добавляется строка о враче (§5).

Заметка, самочувствие и «Приняли лекарство?» правятся своими существующими шагами и не
дублируются. «Отмена» (и «Записать давление» / «Записать сейчас») посреди правки
отменяет её без сохранения. Повторное «✏️ Изменить» заново резолвит «последнюю».

У архивной сводки «✏️ Изменить» (`m:arch:edit`) правит **только что созданную** запись
(id из контекста сохранения `m_id`, момент `m_arch_ts` сохраняется), а не «последнюю» по
`timestamp` — архив можно вносить не в хронологическом порядке.

## 8. Отмена и устаревшие кнопки

- `m:cancel` («Отмена», есть на каждом свободном вводе и в калькуляторе) — сброс черновика
  и FSM, главное меню; ничего не сохраняется.
- `menu:back` («В меню») — главное меню.
- Устаревшие кнопки без черновика (калькулятор, мультивыбор, «Приняли лекарство?» и др.
  при отсутствии `m_id`/состояния) — молча в главное меню (`_to_menu`); кнопки архивного
  черновика с обычными callback'ами показывают сводку архива (`_archive_guard`) — ничего
  не планируют и не пишут.
- Неизвестный callback в области `m:*` и любой непринятый callback — fallback-роутер
  отвечает уведомлением «Это сообщение устарело» (§8, U8).
- Чужой id в callback (`m:med:pick:{id}`, `m:noremeasure:{id}`) — мягко, без деталей
  («Такой записи нет» / идемпотентное подтверждение); чужие данные не раскрываются (§7.1).

## 9. Архивные записи: отличия того же флоу

Числовой поток архива (§6.10) использует **тот же** калькулятор (`m:key:*`, те же
`m_sys`/`m_dia`/`m_pulse`/`m_buf`), но момент измерения задаётся явно до калькулятора:

1. «Когда?» — «Сегодня» / «Вчера» / «3 дня назад» / «Неделю назад» / «Другая дата»
   (`set:archive:date:*`, `ДД.ММ[.ГГГГ]`, год — текущий, не позже сегодняшней);
2. «Во сколько?» — «08:00» / «13:00» / «21:00» / «Другое» (`set:archive:time:*`, `ЧЧ:ММ`);
   будущий момент — «Время измерения не может быть в будущем», повтор ввода;
3. систолическое → диастолическое → пульс — как §3;
4. сохранение — INSERT с указанным `timestamp`; сводка «✅ Записано за 12.03.2025, 08:00» +
   кнопки `m:arch:edit` / `m:arch:note` / `m:arch:med` / `m:arch:feel` / `m:arch:more`
   («➕ Ещё запись») / `m:arch:menu`.

Быстрый ввод (`set:archive:quick`) — одна строка `ДД.ММ[.ГГГГ] ЧЧ:ММ САД/ДАД [пульс]`
(«12.03 08:30 135/85 72»); порядок проверок как в пошаговом: момент, затем значения.
Не распознано — «Не понял формат. Пример: 12.03 08:30 135/85 72» + «Отмена».

Отличия от обычной записи: повторный замер не планируется; «Приняли лекарство?» — только
исторический флаг (без выбора лекарств и `medication_logs`); строка «обсудить с врачом»
не показывается; дубль за ту же минуту всё так же отсекается («Это давление уже записано»).

## 10. Идемпотентность и конкурентность (§7.2)

- **DebounceMiddleware** — 1.5 с на callback-кнопки флоу (`m:*`): повторный тап той же
  кнопки игнорируется, ответ «Уже записываю…». Из-под дебаунса выведены действия без
  записи в БД: цифры/«⌫»/«C» калькулятора (`m:key:…`) и чекбоксы мультивыбора
  (`m:med:pick:…`) — экран редактируется на каждое нажатие. На остальные callback'и —
  общий throttle 1 с.
- Один черновик на пользователя: повторное «Записать давление» перезаписывает черновик.
- Сохранение идемпотентно: дедуп по `user_id` + `timestamp` (округление до минуты) под
  общим asyncio-локом; повторный вызов с тем же черновиком дубль не создаёт.
- Опциональные шаги привязаны к `m_id` сохранённой записи, а не к «последней».
- `med_remeasure` — не более одного активного на `measurement_id`; отметка лекарств
  идемпотентна за локальные сутки (`INSERT … WHERE NOT EXISTS` под локом приёмов).
- Правка — UPDATE одной строки, все три поля одним стейтментом (параллельные правки не
  смешивают значения).
- Сессия БД — на операцию; сначала commit, потом ответ пользователю.
